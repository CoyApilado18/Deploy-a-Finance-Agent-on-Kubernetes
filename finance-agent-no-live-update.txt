FINANCE AGENT GAVE NO LIVE DATA IN THE KAGENT DASHBOARD
=======================================================
Date: 2026-10-12
Components: kagent 0.10.2 (kagent-adk runtime, google-adk inside it),
            kmcp controller 0.3.0 (agentgateway stdio adapter),
            finnhub-tools MCP server (FastMCP 3.0.0, Python 3.12)
Related docs: kagent-deploy.txt (deploy setup), cali-migration.txt (DNS fix)

Result: FIXED. The agent now gets its tools reliably. Three test questions
        (one per Finnhub tool) all completed with live data, and the agent
        logged 0 MCP connection errors.


-------------------------------------------------------------------------
SYMPTOM
-------------------------------------------------------------------------
In the kagent dashboard (kagent dashboard -> http://localhost:8082), a
conversation with kagent/finance-agent asking for Apple's current stock
price got this answer:

    Summary
    I currently do not have access to a real-time stock market data tool or
    live market feed to fetch the exact, up-to-the-second stock price for

    -> completed, tool get_stock_quote, AAPL $340.76 ...

So the setup was right, but the tools were only available SOME of the time.

-------------------------------------------------------------------------
ROOT CAUSE
-------------------------------------------------------------------------
A race between two numbers that are almost the same:

    server cold start per MCP session   ~3.7 - 5.1 s (up to ~20 s when cold)
    agent's MCP connect timeout          5.0 s

How the pieces fit:
  - kagent deploys a "type: command" MCP server as an MCPServer with
    transportType: stdio. The pod runs agentgateway on port 3000 (HTTP,
    /mcp). For EVERY new MCP session, agentgateway starts the configured
    command (python src/main.py) and talks to it over stdin/stdout.
  - The agent (google-adk) opens a new MCP session when it handles a
    request (here: one per dashboard message; it closes the toolset when
    the runner closes). So every question pays the full server start time.
  - If the server takes longer than 5.0 s to answer the MCP "initialize"
    request, the client gives up, retries once, and if that also takes over
    5 s, continues WITHOUT tools.

Why the CLI test worked and the dashboard didn't: luck. The server
happened to start in under 5 s for the kagent invoke request, and just
over 5 s for both attempts from the dashboard. It wasn't a dashboard
vs. CLI difference. Both use the same A2A endpoint and the same code path.


-------------------------------------------------------------------------
FIX
-------------------------------------------------------------------------
File: finance_agent/finance_agent/mcp_tools.py

Give the MCP connection a 30-second connect timeout instead of the 5 s
default:

    # The finnhub-tools server is started fresh (stdio) for every MCP session and
    # takes ~4-5 s to boot, which is right at ADK's 5 s default connect timeout.
    _MCP_CONNECT_TIMEOUT = 30.0
    ...
        if headers:
            connection_params = StreamableHTTPConnectionParams(url=url, headers=headers, timeout=_MCP_CONNECT_TIMEOUT)
        else:
            connection_params = StreamableHTTPConnectionParams(url=url, timeout=_MCP_CONNECT_TIMEOUT)

Why 30 s: comfortably above the worst start time seen (~20 s right after
a fresh deploy), but still short enough that a really dead server fails
in reasonable time.

Is editing this file OK? Its header says "AUTOGENERATED, DO NOT EDIT".
kagent regenerates it only through "kagent add-mcp", and with
agentName "finance-agent" (hyphen) it never does (see kagent-deploy.txt,
Fix 4/5). So this edit stays. If the file is ever regenerated, re-apply
the timeout.

Trade-off: when the server is slow to start, the agent now WAITS for it
(about 5 s, sometimes more) instead of answering without tools. Answers
take a bit longer but contain live data.

Verified locally before deploying:
    get_mcp_tools()[0]._connection_params -> http://finnhub-tools:3000/mcp timeout= 30.0
