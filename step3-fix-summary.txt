FIX 1: agent-card.json (agent crashed on startup)
-------------------------------------------------------------------------
File: finance_agent/finance_agent/agent-card.json

WHAT WAS WRONG
  We had cut the agent card down to three fields:
      { "name": ..., "description": ..., "version": ... }

  When the kagent runtime starts (kagent-adk cli.py, the "run" command),
  it does this:
      agent_card = AgentCard.model_validate(json.load(f))
  That checks the file against the A2A (Agent-to-Agent protocol)
  AgentCard schema. I ran that check inside the real runtime image, and
  our three-field card failed:
      5 validation errors for AgentCard
      capabilities        Field required
      defaultInputModes   Field required
      defaultOutputModes  Field required
      skills              Field required
      url                 Field required
  The container would have crashed before serving a single request.

WHY THE FIELDS MATTER
  The agent card is the agent's "business card" in the A2A protocol.
  Other agents, the kagent controller, and the dashboard fetch it from
  /.well-known/agent-card.json to find out:
    - where the agent lives (url)
    - what it supports (capabilities, e.g. streaming)
    - what kinds of input and output it handles (defaultInput/OutputModes)
    - what it can do (skills)

WHAT I DID
  Put the full structure back with finance-specific values:
    - name: "finance_agent". This matches the agent name in agent.py and
      the project name. The earlier "finance_research_agent" didn't
      match.
    - description: the finance research description
    - version: 0.1.0
    - a skill named "stock_research", tagged finance/stocks/market-data

VERIFIED
  Ran AgentCard.model_validate inside the kagent-adk image, and the
  result was VALID. The running agent also serves the card at
  http://localhost:8080/.well-known/agent-card.json (HTTP 200).

FIX 2: kagent.yaml (we had made up our own format)
-------------------------------------------------------------------------
File: finance_agent/kagent.yaml

WHAT WAS WRONG
  We had rewritten the file in a format that kagent 0.10.2 doesn't use:
      name: finance_agent
      model:
        provider: Gemini
        name: gemini-3.6-flash
      mcp_servers:
        - name: finnhub-tools
          command: python
          args: ["-m", "finnhub_tools"]

  The CLI that `kagent init` generated uses different keys:
      agentName, language, framework, modelProvider, modelName,
      description (and mcpServers for tools)

  There were two problems:
    a) The CLI wouldn't recognise our keys, so they would be ignored or
       cause errors in kagent run, build, and deploy.
    b) Even in the right format, declaring "finnhub-tools" now would be
       wrong. The server doesn't exist yet. The generated mcp_tools.py
       would point the agent at http://finnhub-tools:3000/mcp, and the
       agent would fail trying to connect to it.

HOW MCP SERVERS ARE MEANT TO BE ADDED
  You don't add them by hand. The `kagent add-mcp` command (flags:
  --command, --arg, --env, --build, --image, --remote) writes the
  mcpServers entry into kagent.yaml. kagent then regenerates
  finance_agent/mcp_tools.py and docker-compose.yaml from it. We'll do
  that in Step 4, once the Finnhub server exists.

WHAT I DID
  Went back to the CLI's own format and filled in the empty description:
      agentName: finance_agent
      language: python
      framework: adk
      modelProvider: gemini
      modelName: gemini-3.6-flash
      description: "A finance research agent that fetches real-time
                    stock data and provides market analysis."
  (The original also had an updatedAt timestamp line, which the CLI
  maintains itself.)

FIX 3: Dockerfile (image would not build)
-------------------------------------------------------------------------
File: finance_agent/Dockerfile

WHAT WAS WRONG
  Both `kagent run` and `kagent build` build from this Dockerfile. The
  build failed at:
      RUN uv sync
  with the error:
      runc run failed: ... exec: "/bin/sh": stat /bin/sh:
      no such file or directory
      failed to solve: process "/bin/sh -c uv sync" did not complete
      successfully: exit code: 1

ROOT CAUSE
  The base image ghcr.io/kagent-dev/kagent/kagent-adk:0.10.2 is
  "distroless". To keep the attack surface small, it contains only
  Python and the agent runtime. I inspected the image and confirmed:
    - there is no /bin/sh
    - there is no uv
    - PATH=/.kagent/.venv/bin:...
    - ENTRYPOINT = kagent-adk run --host 0.0.0.0 --port 8080
    - it runs as non-root user 65532
  A shell-form RUN instruction ("RUN uv sync") needs /bin/sh, so it
  can't run on this image.

WHY REMOVING THE STEP IS SAFE
  - Our only dependency (pyproject.toml) is google-adk.
  - The base image's virtualenv already includes google-adk 1.38.0
    (plus kagent-adk 0.3.0).
  - uv sync would actually have DOWNGRADED google-adk to the 1.28.1
    pinned in pyproject.toml, giving us an older ADK than the runtime
    was built against.

WHAT I DID
  Replaced the "RUN uv sync" line with this comment:
      # The kagent-adk base image is distroless (no /bin/sh, no uv) and
      # already ships google-adk in /.kagent/.venv, so there is nothing
      # to install here.

CAVEAT
  The Dockerfile header says "AUTOGENERATED FILE: DO NOT EDIT".
  Re-running `kagent init` would overwrite this fix, so apply it again
  if you ever re-scaffold.

FOLLOW-UP TO CONSIDER
  pyproject.toml still pins google-adk==1.28.1. That only affects your
  local .venv (VS Code autocomplete), not the container. You could bump
  it to 1.38.0 so your editor matches the runtime.

FIX 6: "No API key was provided" in the kagent run chat
-------------------------------------------------------------------------
Files: finance_agent/.env (renamed from .env.local), .gitignore,
       README.md

SYMPTOM
  `kagent run` opened the chat, but every message got this reply:
      No API key was provided. Please pass a valid API key.

WHAT WAS WRONG
  `docker inspect` on the container that `kagent run` created showed:
      GOOGLE_API_KEY=        (empty)
  docker-compose.yaml passes the key with:
      - GOOGLE_API_KEY=${GOOGLE_API_KEY}
  docker compose fills in ${...} values from only two places:
    1. variables exported in the terminal that ran the command
    2. a file named exactly ".env" in the project folder
  The key was in ".env.local", which nothing loads automatically, so
  compose filled in an empty string and Gemini rejected the request.

WHICH FILE KAGENT READS (checked against the kagent 0.10.2 binary)
  kagent run     -> docker compose -> auto-loads ".env" only
  kagent deploy  -> only the file you pass with --env-file
                    (its help text uses: --env-file .env)
  kagent build   -> no keys; they are never baked into the image
  The only places ".env.local" appears in the binary are templates: an
  .env example generated by `kagent mcp init` ("Copy this file to
  .env.local") and .gitignore templates. No command loads it.

WHAT I DID
  - Renamed finance_agent/.env.local to finance_agent/.env, so it's one
    file holding both GOOGLE_API_KEY and FINNHUB_API_KEY. (A symlink
    .env -> .env.local was tried first, then dropped as confusing.)
  - .gitignore now ignores .env (plus .venv/ and __pycache__/).
  - README: the "Create the environment file" step now writes .env, and
    explains why the name must be .env. The other .env.local
    references now say .env.
  - Use `kagent deploy . --env-file .env` when deploying.

VERIFIED
  - With nothing exported, `docker compose config` resolves
    GOOGLE_API_KEY from .env.
  - Recreated the container: GOOGLE_API_KEY is set inside it.
  - Test chat message completed, and Gemini answered: "I am a financial
    research assistant that fetches real-time stock market data,
    compares company metrics, and provides clear market analysis..."

    pass FINNHUB_API_KEY to that container in Step 4.
